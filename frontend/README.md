# Indian Market Lab frontend

The frontend is a single-page SvelteKit research console backed by the root
FastAPI service in `server.py`.

## Start the stack

From the repository root:

```bash
git pull --ff-only
uv sync
uv run uvicorn server:app --reload --host 127.0.0.1 --port 8000
```

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open:

```text
http://localhost:5173
```

Vite proxies `/api` to the FastAPI process on port 8000.

## What the console controls

Research mode can:

- launch the V4 hindsight oracle
- train the V4 tree student
- run the causal V4 policy
- launch the legacy FQI/controller experiments
- launch any other `src/ml/*.py` experiment through the Advanced runner
- override exposed experiment parameters such as capital, holdings, PSO
  particles/iterations/restarts, costs, model list and year
- monitor persistent run status and logs
- inspect portfolio metrics, equity history, action history and research
  artifacts
- inspect the retained V4 action-value matrix for a decision state

The server stores UI-launched run metadata and logs under:

```text
reports/ui_runs/<run-id>/
```

## Market chart

The chart prefers:

```text
data/processed/equities_adjusted/
```

because that layer preserves the true NSE open/high/low/close/volume fields.

The current historical dataset is daily, so the native time quantum is one
market session. The UI provides:

- 1D native bars
- 1W resampling
- 1M resampling
- 3M resampling

It does not pretend daily data are intraday candles. Intraday intervals require
a future intraday source.

## Human game

Human Game mode:

- starts with configurable capital, maximum distinct holdings, start date and
  historical lookback length
- stitches prior-year OHLCV when necessary so the starting decision has real
  chart history instead of a single candle
- shows only market information available through the current historical date
  and hard-cuts all future price bars
- uses whole shares with a minimum non-zero order of one share
- supports adding to an existing holding / averaging down or up
- supports partial selling / trimming
- supports order sizing by shares, rupee notional, fraction of portfolio
  equity, or target portfolio weight
- supports HOLD, BUY/ADD, SELL/TRIM, SET TARGET, SWITCH and LIQUIDATE decisions
  at the next market open
- tracks average cost, position weight, unrealized P&L, realized P&L, fees,
  turnover, cash, equity, CAGR, Sharpe, Sortino, Calmar and drawdown
- uses the same Indian delivery cost/slippage functions as the research
  backtester

The game session is in-memory and resets when the FastAPI process restarts.

## V4 experiment sequence

Use the Research tab in this order:

1. Portfolio Oracle V4
2. Portfolio Student V4
3. Portfolio Policy V4

The Actions dock becomes a decision-state action-value matrix after the student
run. It compares predicted Q with hindsight oracle Q, oracle rank, regret,
future return, future drawdown and turnover for every retained candidate action
at that state.

The PSO action space itself is continuous/combinatorial. The matrix therefore
shows all retained candidate actions generated by the oracle search; it is not
a literal enumeration of every mathematically possible portfolio.
